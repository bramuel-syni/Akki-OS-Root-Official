# M14 · Answering Service + Seam + Async + Mkondo

## OBJECTIVE

Close **C.15** (Mkondo hand-off registry) and **C.17** (answering service + async delivery). Every cross-app crossing of governed work becomes explicit at the boundary: a `HandoffContract_v0` shape-frozen at W1, a Mkondo registry that refuses malformed / dual-hatted hand-offs at request time (W2), Mongo-backed collections for the async request/delivery/webhook triangle (W3), and real async webhook delivery signed with per-tenant Ed25519 keys minted at M13-W2 (W4). W5 is the milestone seal.

## MUST DO

1. **W1 · Hand-off contract v1 shape-freeze** — consume the already-sealed `services/handoff/contracts.py` + `contracts/handoff_contract.py` surface; author an invariant test file that freezes the shape (required-field set + `extra='forbid'` + `frozen=True` + `handoff_id` regex `^ho_[a-z0-9_-]+$` + register/attest refusal surface + sha256-pinned model_json_schema snapshot). Additive-only per SO §3.8: no edit to the sealed contract module; the invariant test is the new surface. `canon_ref: Canon 15 §33 (four required fields verbatim: what · shape · identity · receipt) + CA1-009 (every cross-app crossing expressed in a HandoffContract_v0 before it ships) + SO §3.8 (thin-kernel additive-only).`

2. **W2 · Mkondo registry + checkpoint runtime** — a new module `services/mkondo/registry.py` that (a) admits a `HandoffContract_v0` at request time, (b) refuses malformed contracts via pydantic ValidationError propagation, (c) refuses dual-hatted contracts where `identity_source.actor_id == identity_destination.actor_id` (structural role separation per Canon 8 §W11 one-task-one-identity), (d) emits one ledger intent per admitted hand-off via the unified `services.ledger_writer.emit_intent` surface. Structural role separation: registry does NOT sign hand-offs; that stays at W4. `canon_ref: Canon 15 §33 + Canon 8 §W11 + Canon 1 §62 (single-writer ledger).`

3. **W3 · `asks` + `deliveries` + `webhook_endpoints` collections on Mongo** — three new Mongo collections + their models under `services/answering_service/collections/`. Per-tenant scope per M11 (`t_<tenant_id>` databases with insert-only writer role). Each collection carries a frozen pydantic model + append-only write surface + read surface. `canon_ref: Canon 17 §4 (answering service triangle: ask · delivery · webhook_endpoint) + Canon 3 §B.7 (per-tenant provisioning) + M11 (tenant DB provisioning sealed).`

4. **W4 · Real async webhook delivery signed with per-tenant Ed25519** — a new module `services/answering_service/webhook_delivery.py` that (a) reads an `ask` + its confirmed `webhook_endpoint`, (b) constructs a `delivery` payload, (c) signs the payload with the tenant's Ed25519 key via `services.watch.signature_primitive.sign` (M12b-W1 sealed) or the KMS-envelope-wrapped tenant signing key (M13-W2 sealed · runtime decision at W4-open), (d) records the delivery under the `deliveries` collection with `state='sent'` and the signature attached. Structural role separation: webhook delivery does NOT wrap / unwrap KMS envelopes directly; that stays at `services.kms.envelope` per Canon 8 §W11. `canon_ref: Canon 17 §4 + Canon 8 §W11 + M12b-W1 (Ed25519 primitive) + M13-W2 (per-tenant KMS).`

5. **W5 · SEAL** — full milestone seal at Commit-A of an integration test that authors a HandoffContract_v0, admits it through the Mkondo registry, creates an ask, confirms a webhook_endpoint, delivers a signed webhook, verifies the delivery record, all end-to-end. `canon_ref: SO §6.2 EXIT clause (milestone gate closes on a test that binds all sub-waves' evidence).`

## MUST NOT

- Admit a hand-off with `identity_source == identity_destination` (dual-hatted refusal per Canon 8 §W11 one-task-one-identity). `canon_ref: Canon 8 §W11 verbatim.`
- Route webhook delivery through any surface that has NOT been signed with the tenant's Ed25519 key (evidence-never-fabricated per Canon 8 §W1). `canon_ref: Canon 8 §W1 + M12b-W1 signature primitive.`
- Emit more than one ledger intent per admitted hand-off (single-writer discipline per Canon 1 §62). `canon_ref: Canon 1 §62.`
- Widen the `HandoffContract_v0` shape after W1 seals without a ceremony (shape-freeze mandate: the snapshot hash pinned at W1 is authoritative until re-ratified). `canon_ref: SO §3.10-α (closed-schema discipline) + Canon 15 §33.`
