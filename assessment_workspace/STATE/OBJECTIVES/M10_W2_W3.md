# M10-W2/W3 · The Ledger's Operational Wire

## OBJECTIVE

The sealed hash-chained ledger becomes independently verified in operation: a verifier that runs under credentials the writer does not hold, keeps its own append-only receipt store, publishes head hashes to tenant receipt endpoints on a nightly + on-demand cadence, and wires SEV-1 evidence (security-group page + Watch signal, never action) on any chain break.

## MUST DO

1. **Verifier credential-separation (C3 principle)** — the verifier's construction refuses under any credential handle that is not `LEDGER_VERIFIER_CRED_HANDLE`, and the writer's code cannot import the verifier's handle. `canon_ref: Canon 1 §62 (single-writer + peer authority) + B-M10-Q2 (verbatim: "verifier cannot share anything with the thing it verifies").`
2. **Verifier's own append-only receipt store** — no update method, no delete method, no re-append of an existing `(tenant_id, head_seq)` pair; persistence namespace scoped by credential handle. `canon_ref: Canon 3 §9.3 (BR-15 append-only) + B-M10-Q2.`
3. **Head-hash publication to the tenant receipt endpoint** — `HeadHashPublication` frozen 5-field certificate-like record, append-only per-tenant JSONL, M3 forward-compat banned-field-exclusion (no confidence/score/strength/probability). `canon_ref: Canon 1 v1.0 B.4 verbatim ("Publishes head hash to the tenant's receipt endpoint").`
4. **Cadence scheduler primitive** — closed 2-tuple alphabet `("nightly", "on_demand")`, `CadenceIntent` frozen record, `UnknownCadenceIntentRefused (LEDGER-VERIFIER-CADENCE-001)` on non-alphabet kinds, and the cadence module NEVER invokes `verify_chain()` (single-responsibility discipline). `canon_ref: B-M10-Q2 (verbatim: "Cadence: nightly per tenant + on-demand · R-18 effect 12") + SO §3.10-α (tuple[str] discipline).`
5. **SEV-1 wire on chain break — security-group page AND Watch signal** — `wire_sev1_on_chain_break()` emits BOTH a `Sev1Page` (paging endpoint) AND a `LedgerChainBreakSignal` (Watch evidence store, DISTINCT from the closed six-kind sever-certainty registry) on `break_at_seq is not None`; emits NEITHER on intact chain. Evidence-never-action: no import of `services.watch.mkono` or `services.ledger_writer` from any of the three new W3 modules. `canon_ref: B-M10-Q2 (verbatim: "a chain break pages the security group per B.10 and is additionally recorded as a Watch signal, never as an action") + Canon 8 §W1 (eyes-never-act) + Canon 8 §Line 31 (closed-6-registry preserved).`

## MUST NOT

- The verifier shares any credential with the writer. `canon_ref: Canon 1 §62 · B-M10-Q2 C3 principle.`
- The SEV-1 wire performs any custody action (no Mkono call, no ledger write, no reversal). `canon_ref: Canon 8 §W1 (eyes-never-act) + owner run order 2026-09-18T~21:15Z ("evidence-never-action discipline").`
- The chain-break Watch signal widens the closed six-kind sever-certainty registry. `canon_ref: Canon 8 §Line 31 (six-registry is closed; membership additions are ceremonies).`
- Any new certificate-like record on the operational-wire surface carries `confidence` / `score` / `strength` / `probability` fields. `canon_ref: owner run order 2026-09-18T~21:15Z (M3 verdict-schema discipline preempted).`
