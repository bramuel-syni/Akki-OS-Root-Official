# M10-W4 · Writer Consolidation

## OBJECTIVE

Fold five legacy per-service writers (refusal, countersign, northena, deletion, memory) into the unified hash-chained single-writer at `services.ledger_writer.main.append_intent`, with per-writer replay-proof (legacy row-hash reproduction · zero rows lost) as the precondition for admission, and legacy stores going read-only at cutover — never rewritten.

## MUST DO

1. **W4a · refusal writer replay adapter** — canonicalise the legacy `NorthenaLedgerRow_v1` refusal-terminal row shape, hash-anchor via `payload_ref = sha256_hex(legacy_refusal_canonical_bytes(row))`, and map every semantic field into a unified `LedgerIntent` (run_id, task_id ← trace_id, event_type="refuse", decision="refused", reason_code ← stamp_audit["refusal_family"], resource_* ← artifact_ref, at ← wall_clock). Replay-proof test on the unified writer with ≥5 diverse legacy rows. `canon_ref: Canon 1 §62 (single-writer discipline · "no service keeps a local log constituting a separate account") + Canon 1 §71 (no sibling ledger) + owner run order 2026-09-18T~21:15Z verbatim.`
2. **W4b · countersign writer replay adapter** — same-shape adapter for the countersign event stream (structure to be discovered from `contracts/` and `services/countersign*` at open). `canon_ref: same as W4a.`
3. **W4c · northena writer replay adapter** — same-shape adapter for the legacy Northena non-refusal event rows. `canon_ref: same as W4a.`
4. **W4d · deletion writer replay adapter** — same-shape adapter for the deletion event stream. `canon_ref: Canon 1 §71 (data class not sibling ledger) + retention rules.`
5. **W4e · memory writer replay adapter** — same-shape adapter for the memory-write-back stream. `canon_ref: same as W4a.`

Every sub-wave (W4a…W4e) satisfies four common structural properties:
- Deterministic canonicalisation function (two calls on the same legacy row produce byte-identical output).
- `payload_ref` binds sha256_hex of canonical bytes (row-hash reproduction).
- Zero rows lost on ≥5 diverse legacy rows replayed through the unified writer.
- AST: adapter does NOT import any legacy write surface (read-only-at-cutover · owner mandate verbatim).

## MUST NOT

- Rewrite any legacy store from a replay adapter. `canon_ref: owner run order 2026-09-18T~21:15Z verbatim ("Legacy stores go read-only at cutover · never rewritten"); §6.4 pre-ruling reaffirms.`
- Import from `services.northena.ledger` (legacy Mongo write surface) or from `services.compliance.refusal_ledger` (legacy emitter) — or the equivalent legacy write surfaces for each subsequent sub-wave. `canon_ref: same.`
- Lose any legacy row's semantic content across replay. `canon_ref: owner run order verbatim ("zero rows lost").`
- Introduce a sibling ledger for any of the five event classes. `canon_ref: Canon 1 §71 verbatim ("When it gains a new class of recorded event, the record gains a data class, not a second ledger").`
- Land a sub-wave whose replay-proof test does not pass. `canon_ref: owner precondition verbatim ("Per-writer replay test PASSING is precondition to landing that writer").`
