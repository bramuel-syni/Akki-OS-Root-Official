Failure Posture Enumeration
failure_posture_v1 — Draft for owner ratification · Closes Document 0 G-11
1   The Platform Default
FP-1  Every component in the Trusted Computing Base fails closed by default. An evaluation that cannot complete — configuration unset, a dependency unreachable, a check erroring — refuses the operation it governs. This is the default; §3 lists the components that correctly depart from it, and why.
FP-2  A gate whose governing configuration is unset or fails integrity verification at load refuses by default rather than passing by default. This absorbs security_architecture_v1's SEC-4 (MOAC), SEC-6 (the distance gate), and SEC-7 (the admission probe) as one rule rather than three restatements of it — an unconfigured gate is a closed gate, platform-wide, not per-component.

3   The Departures — Where Fail-Safe-Open Is Correct
Two departures from §1's default, both already correct in the system as built, now stated as deliberate rather than left to be discovered.
FP-3  Mtafiti's read path fails safe-open: a write failure never blocks a query against already-committed estate composition. The alternative — refusing to answer “what exists” because “what changed most recently” cannot be confirmed — would make an outage indistinguishable from data loss to everyone reading the registry, which is a worse failure than serving slightly stale data marked as such.
FP-4  The Watch's already-active containments persist through a Watch outage rather than lapsing. This is fail-closed for new decisions and explicitly not fail-open for standing ones — the two are evaluated separately, and conflating them would silently release every contained actor the moment the Watch itself failed, which is precisely when containment matters most.
Recovery time objective and recovery point objective for the Ledger writer specifically are covered in the Business Continuity Annex (document 8 of this set), not restated here — this document specifies posture per component; that one specifies how long a failure may last and how much may be lost before it is a breach in its own right.
4   Standing
A component added to the Trusted Computing Base under tcb_enumeration_v1's own standing clause is added here in the same turn — posture, failure types, and preserved state, not deferred to a later pass. §1's default applies until stated otherwise; a new TCB member that departs from it states so explicitly, the way §3 does for Mtafiti and the Watch.
