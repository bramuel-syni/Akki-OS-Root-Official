1   SyniSense — The Chokepoint
1.1. The Chokepoint
Verdict: Three of four fully met. Self-protection is partial — build-time gates exist; runtime tamper-resistance for the loaded policy is proposed below, not yet built.
SEC-1  SyniSense's custody-sequence policy and network allowlist MUST be integrity-verified at load — a signature or hash comparison against the value recorded in the Rule Registry — so that a runtime modification is detected, not merely prevented by the absence of an edit path.  [Closes the remaining gap in 1.1]
2   The Watch — Mkono (Response)
2.1. Mkono, the deterministic response half
Verdict: All four met, directly from canon text. The strongest-evidenced monitor on the platform after the chokepoint.
3   The Watch — Grey Mirror (Macho)
Grey Mirror is not itself evaluated as a reference monitor. Per tcb_enumeration_v1, Macho is learned and holds no decision authority — “it cannot block, throttle, mark, reroute, or notify. Its sole output is a verdict” (A2, verified verbatim). ADV_ARC.1 applies to components that mediate and decide; Macho detects and proposes. Its self-protection is covered separately, under C3 below, as the subject the witness watches — not as a monitor in its own right.
4   The External Witness (C3)
4.1. The witness — the mechanism that makes 2.1's self-protection checkable
Verdict: Structurally sound and directly evidenced. The one open item is the schedule's actual cadence — a ruling, not a design gap.
5   MOAC
5.1. The acceptance gate
Verdict: Non-bypassability asserted, not demonstrated. The other three properties do not exist in canon and are specified fresh immediately below.
SEC-2  MOAC's acceptance criteria MUST be held in versioned, Rules-Service-governed configuration — the same discipline as SyniSense's custody policy — with integrity verified at load. No criterion is editable by the run it measures, by construction rather than by convention.  [Self-protection]
SEC-3  MOAC operates entirely within Targeta's boundary and reads only the run artefacts Targeta produces. It does not query Solva, Mtafiti, or any other engine to reach its decision.  [Domain separation]
SEC-4  MOAC MUST refuse to evaluate — not default-accept, not skip — if its criteria configuration is unset or fails integrity verification at load, on the same pattern as A17.9's execution-mode raise.  [Secure initialisation]
SEC-5  Every path by which a run's result could be treated as accepted MUST be enumerated and shown to pass through MOAC's evaluation, in a build-time test comparable to SyniSense's negative-scan gate.  [Non-bypassability, demonstrated not asserted]
6   DAP-31 — The Artefact Egress Distance Gate
6.1. The distance gate
Verdict: Three of four met by the amendment that created it. Secure initialisation is the one gap.
SEC-6  DAP-31's probe MUST refuse to run — and MUST refuse egress by default in that state — if the reproduction threshold, sample size, or probe design values are unset. Absence of configuration is a refusal condition, not a bypass.  [Secure initialisation]
7   DAP-32 — Admission-Integrity Probe
7.1. The mirage battery
Verdict: Three of four met, inherited directly from the mirage's own established properties. Secure initialisation is the gap, same shape as 6.1's.
SEC-7  DAP-32's battery MUST refuse to admit a model — default to refusal, not default to pass — if battery composition or deviation thresholds are unset.  [Secure initialisation]
SEC-4, SEC-6, and SEC-7 are the same rule applied three times: an unconfigured gate refuses. Worth ratifying once, as a platform-wide default under Attribute 11 (Failure Posture), rather than as three separate clauses that happen to say the same thing — flagged for the Failure Posture Enumeration (document 5 of this set) to absorb.
8   QA-2 — The Format Gate
8.1. Schema-completeness check
Verdict: Non-bypassability and domain separation reasonably inferred from its position in the loop; self-protection and initialisation are unspecified. Lowest priority to close — QA-2 gates form, not access or disclosure.
9   Summary
Seven requirements (SEC-1 through SEC-7) close every proposed gap above except QA-2's self-protection and initialisation, left open as the lowest-consequence item on this list — named rather than silently dropped.

[TABLE 1]
Property | Demonstrated as
Non-bypassability | Exactly one function may invoke the external model client; a negative-scan build test fails the build if any second path is introduced. Demonstrated at build time, on every build, not asserted once.
Self-protection | Custody-sequence logic and the closed-network allowlist are held in configuration outside the reach of any subject the crossing mediates. Runtime integrity verification of the loaded policy is not yet specified — the one property this monitor does not yet fully meet.
Domain separation | The chokepoint operates entirely within SyniSense's own boundary; it does not reach into Solva, Targeta, or Mtafiti to make its decision.
Secure initialisation | The closed outbound network and allowlist are build-time invariants, present before the component accepts its first request — there is no partially-initialised state in which the chokepoint runs without them.

[TABLE 2]
Property | Demonstrated as
Non-bypassability | “Totality of sight” (A3, verified verbatim): no path reaches the estate or a model outside the Watch's observed surface, held by two independent proofs, static and runtime. This is Mkono's mediation guarantee — it acts on everything Macho can see, and Macho sees everything.
Self-protection | Mkono “contains no model, no content parsing, no reasoning — a deterministic mapping from verdict properties to actions, small enough to verify exhaustively” (A2, verified verbatim). It reaches behind the verdict seam for nothing; there is no surface for a mediated party to tamper with beyond the seam itself.
Domain separation | Mkono and Macho “meet at exactly one interface: a signed, replayable verdict” (A2). The hand never inspects raw behaviour. This is domain separation stated in the source text, not inferred.
Secure initialisation | The Watch's own ceremony — slowest countdown, external witness — governs any change to Mkono's policy tables (A5.8, A5.11), which is the initialisation discipline for a component whose “policy” is closer to configuration than code.
[/TABLE]
