The Determinism Inventory
determinism_inventory_v1 — Draft for owner ratification · Closes Document 0 G-10
1   Classification
Deterministic: given the same input and state, the same output, reasoned about exhaustively. Learned: statistically characterised, not exhaustively reasoned about, whatever its accuracy. A component is one or the other; where a named subsystem contains both, it is split, consistent with tcb_enumeration_v1's treatment of Solva, Targeta, and the Watch.
2   Human Oversight Against Article 14
Where a human, not a deterministic component, is the check on a learned component's output, Article 14 names five distinct capabilities. The platform's own ruling loop — every decision recorded across this programme, from the four owner rulings at the start through every parked ruling since — is mapped against each separately, because a loop that serves one well does not thereby serve all five.
3   Findings
Sixteen components classified without ambiguity. One genuinely mixed case — the DAP-32 trigger scan — carried forward from the amendment that created it rather than forced to a single verdict here. Of Article 14's five capabilities, one (override) is strongly evidenced by this canon's own working method; one (automation bias) is directly and deliberately addressed by a named requirement; two (understand-and-monitor, correct interpretation) are plausible but unconfirmed by design intent or by test; and one (halt-to-safe-state) has a specific, named, still-open question — whether CIF can be stopped independent of the run it feeds.
DET-1  Confirm or build a halt mechanism for CIF independent of halting the Targeta run it feeds — closing capability (e) fully rather than leaving it partially evidenced.
DET-2  Where an AI-assisted classification capability is built into Mtafiti, name the deterministic confirmation step before it ships — not after, per this inventory's own method for every other learned component.
This inventory itself should be re-run, not assumed permanent, whenever a new component is added to the platform — consistent with tcb_enumeration_v1's own standing clause. The two share a maintenance obligation because they share almost all their evidence.
