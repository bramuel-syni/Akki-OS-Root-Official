## §11. Root-cause analysis of Wave G3 slot #1 non-fire

Direct inspection of the byte-identical prototype (sha256 `e56871d0…`) revealed the exact fragmented-span structure:

```html
<div style="font-family:var(--head);font-size:24px;line-height:1.35;color:var(--ink);margin-bottom:13px;text-wrap:pretty;">RMS AI holds <span style="border-bottom:1px solid rgba(27,31,39,.25);">86.4 TB</span> across <span style="border-bottom:1px solid rgba(27,31,39,.25);">12 sources</span> — <span style="border-bottom:1px solid rgba(27,31,39,.25);">78% measured</span>, with <span style="color:var(--oxblood);">6 opportunities</span> standing ready.</div>
```

The container `<div>` has FIVE nested `<span>` children (four underlined, one colored). A `document.createTreeWalker(doc.body, NodeFilter.SHOW_TEXT)` iterator visits ~9 separate text nodes:

1. `"RMS AI holds "`
2. `"86.4 TB"` (inside underlined span)
3. `" across "`
4. `"12 sources"` (inside underlined span)
5. `" — "`
6. `"78% measured"` (inside underlined span)
7. `", with "`
8. `"6 opportunities"` (inside oxblood span)
9. `" standing ready."`

Wave G3's rule `signature: /^\s*RMS AI holds .* opportunities standing ready\.\s*$/` matched **none** of these — the full sentence exists only as `element.textContent` (a computed concatenation), never as a single text-node's `nodeValue`. Slot #2 fired because the census sentence lives in one text node before its trailing `<span>How the estate is measured</span>`.

Wave G4 fix: **element-anchor substitution** (`kind: "element-anchor"`) — walk elements, find the one whose `textContent.trim() === dummyContent.trim()`, assign `.textContent = desired`. This handles fragmented spans automatically because `.textContent` flattens the entire subtree.

The 10 topline tiles have a different root-cause: they're generated by dc-runtime JS at runtime (`measureCards: [{label, value, note}, ...]` at char 1196273 of the prototype). Substitution must happen **after** dc-runtime mounts the Registry surface, and must be **idempotent under re-application** because dc-runtime may re-mount on tab switches / drawer opens / navigation. Wave G4 fix: `MutationObserver` observes `iframe.contentDocument.body` with `childList + characterData + subtree`; every mutation event triggers a debounced (`requestAnimationFrame`) `applyAll()` that re-runs the engine. Idempotency emerges from state — after the value node's `.nodeValue = desired`, subsequent walker passes never match `trimmed === rule.dummy` on that node again.

**Idempotency (Wave G4 CORRECTION 1(b) mechanism):**
- Match only on `trimmed === rule.dummy` (never on `trimmed === desired`). After mutation, the text node holds `desired ≠ dummy`, so subsequent walker passes skip it naturally.

- A pre-Wave-G4 bug where `trimmed === desired` was accepted as "already applied" was fixed — that path false-fired for tile "Share measured" (dummy `78%`, desired `"Not yet measured"`) because the walker hit the LABEL of the *"Not yet measured"* tile first, whose text equals `desired`. Fix: never accept `desired` as a match signal; rely on state-emergent idempotency only.
