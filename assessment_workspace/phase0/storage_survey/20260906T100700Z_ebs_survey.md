That host — an app server, an nginx front, or a bucket-backed HTTP CDN — is where the owner needs to grant access.

**No mounts required, no unmount receipts:** every disk on both hosts was already mounted; no dark-attached EBS surfaced. The read-only scratch-mount step in the survey plan was unnecessary — noting explicitly so the receipt path is clean.

## 4 · Volume/instance provider identification

Both GPU hosts:
- `hostnamectl` context: Ubuntu on a virtio/KVM platform (no `nvme list`, no `/sys/class/nvme/*`).
- Root disk labels: `cloudimg-rootfs` (Ubuntu cloud image) — same 74 GiB disk on both.
- Data volume label naming: `dkgjrkx_akki-storage-3388s` matches **DigitalOcean's block-storage naming convention** for named block volumes (`<region>_<volume-name>`); the "-3388s" prefix is the size in sectors × 8. This points at DigitalOcean Droplets, not AWS EC2.

**"EBS" in owner's shorthand → the block-storage volumes are actually DigitalOcean Block Volumes.** Same class of primitive (attached ext4 block devices), different platform. Both hosts have them attached, both are empty.

## 7 · What owner needs to grant (unchanged from 2026-09-06T09:40Z, restated more precisely after this survey)

To locate audio (if it exists), the owner needs to provide one of:

1. **SSH access (keypair or equivalent) to the DigiCow application server** — the host where the DigiCow app resolves `file://` bare filenames into disk paths. This is a *different* machine from `akki-vm` and `akki-vm-ii`.
2. **Or: the storage-backend URL rewrite pattern** the app applies — e.g., "the app prepends `s3://digicow-media-prod/` to every bare filename before serving". With the pattern + LIST credentials for that bucket, we enumerate audio via boto3 without SSH.
3. **Or: the connection record for a different database** entirely (not `digicow_live`) if audio is stored in a parallel DB the current RDS Data API principal doesn't see (e.g., a media-metadata service DB).

If none of the above exists — i.e., the DigiCow app stores only images and the "audio" corpus is a different product entirely — that's a clean honest finding worth banking too. No wishful classification: the evidence to date says the DigiCow estate we reach carries images, not audio.
