> **§11.1 P172 (V109) verbatim (LOAD-BEARING):**
>
> *"The existing planner pattern is reused unchanged: a deterministic core computes eligibility; a learned layer may only reorder an already-eligible set it receives stripped of the values that decided eligibility; a gate compares learned output against the deterministic baseline; every plan is reproducible from its recorded inputs."*

**Public API (10 exports · owner-set ≤10 ceiling · WITHIN):**

- `PlanInputs` — frozen 3-carrier: `outcome: TargetOutcome` · `register_strata_refs: Tuple[str, ...]` · `seed: int`.  V109 fourth clause: every input the planner reads MUST live here so that the reproducibility witness's `plan_inputs_sha256` binds to the exact input set.
- `EligibilityDecision` — frozen 2-carrier: `eligible_ids: FrozenSet[str]` · `values_that_decided: Mapping[str, Any]`.  V109 first clause: the deterministic core's output.
- `EligibleStripped` — frozen 1-carrier: `ids: FrozenSet[str]`.  V109 second clause: carries ONLY the ids.  Forbidden-name negative-scan against `values_that_decided`, `score`, `value`, `eligibility_value`, `values`, `decision_values`.
- `PlanReproducibilityWitness` — frozen 2-carrier: `plan_inputs_sha256: str` · `plan_output_sha256: str`.  V109 fourth clause: binds sha256 of recorded inputs to sha256 of plan output.
- `PlannerCore` — `@runtime_checkable Protocol`.  Method: `compute_eligibility(*, plan_inputs: PlanInputs) -> EligibilityDecision`.  V109 first clause seam.
- `LearnedReorderLayer` — `@runtime_checkable Protocol`.  Method: `reorder(*, eligible_stripped: EligibleStripped) -> Tuple[str, ...]`.  V109 second clause seam; signature accepts ONLY the stripped carrier.
- `strip_eligibility_decision(decision) -> EligibleStripped` — V109 second clause enforcement.  Strict `type(x) is EligibilityDecision` check refuses subclasses AND duck-typed lookalikes.
- `run_eligibility_gate(*, plan_inputs, planner_core, learned_reorder_layer) -> Tuple[Tuple[str, ...], PlanReproducibilityWitness]` — composes the four V109 clauses.
- `LearnedReorderStrippingViolationError` — V109 second clause refusal.
- `EligibilityGateSlippageError` — V109 third clause refusal.

**Refusals (2):**

1. `LearnedReorderStrippingViolationError` — `strip_eligibility_decision` receives an input that is not an actual `EligibilityDecision` instance.
2. `EligibilityGateSlippageError` — learned reorder output's set-membership diverges from the deterministic baseline (both drop and add cases refused; ordering may differ).

**Reproducibility witness canonicalisation:**

`_canonical_plan_inputs_bytes` walks the frozen-dataclass structure and emits an ASCII UNIT SEPARATOR (`\x1f`)-joined field digest covering: `task`, `domain`, `population.stratum_refs` (sorted), `acceptance.has_per_stratum_dimension`, `acceptance.per_stratum_thresholds` (sorted), `gate_policy`, `test_set_ref`, `constraints.{latency,compute_budget,deployment_target}`, `register_strata_refs` (sorted), `seed`.  `_canonical_plan_output_bytes` emits `\x1f`-joined ordered plan ids.  Both hash via `hashlib.sha256(...).hexdigest()`.  Deterministic and case-agnostic.
