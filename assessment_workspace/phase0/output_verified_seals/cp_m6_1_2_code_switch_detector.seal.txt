> §4.1 P061 (V44): "Recorded per segment: languages[], confidences, and code-switch points where multiple languages occur in one utterance."
>
> §4.2 P065 (V47): "Switch points (position, from-language, to-language, context class) are registered facts with provenance — not preprocessing metadata. They populate the register's code-switch layer and stratify test sets."

Public API:
- `detect_code_switch_points(*, segments: Sequence[AudioSegment], backend: CodeSwitchDetectorBackend) -> List[CodeSwitchPointDetection]`
- `AudioSegment` — **re-exported from CP-M6-1-1** (single source of truth for the §4 per-segment shape · no refactor of CP-M6-1-1).
- `CodeSwitchPoint` (frozen 5-carrier: `position` + `from_language` + `to_language` + `context_class` + `confidence`).  Four §4.2 P065 verbatim carriers + confidence attribution per CP charter (code-switch points annotated with confidence + language-pair).
- `CodeSwitchPointDetection` (frozen 3-carrier: `segment_ref` + `switch_points` tuple + `backend_name` · D10 attribution).
- `CodeSwitchDetectorBackend` (`Protocol` with `backend_name` attr + `detect(segment_ref, duration_s) -> Tuple[CodeSwitchPoint, ...]`).
- `UnratifiedCodeSwitchInferredBackend` (placeholder; satisfies protocol structurally; refuses to detect with `[INFERRED-pending-ratification]` marker per D10 open ruling · RULING_LEDGER row 13).
- Refusals: `SegmentsEmptyError` (re-exported) · `SegmentInvalidError` (re-exported) · `BackendUnratifiedError` (CP-M6-1-2-local class · separate from CP-M6-1-1's homonym so each backend's ratification story is tracked independently).

Pull-seam discipline preserved: **audio bytes DO NOT cross the seam** — only the opaque caller-scoped `segment_ref` handle + `duration_s` metadata. Pure orchestration — no LLM, no HTTP, no filesystem, no direct audio-byte reading. Real backend awaits owner ratification; the seam admits any owner-ratified backend on ratification.
