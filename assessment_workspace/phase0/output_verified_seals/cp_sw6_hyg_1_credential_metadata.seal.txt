**Public API additions (5 new exports on `custody_file`):**

- `CustodyFieldMetadata` — frozen 3-carrier: `field_name` · `value_length_bytes` · `value_sha256`.  Structurally CANNOT carry a raw value (no attribute of that name exists; field set is closed and enforced by `@dataclass(frozen=True)`).
- `CustodyFileMetadata` — frozen 2-carrier: `path` · `fields: Tuple[CustodyFieldMetadata, ...]`.
- `read_custody_metadata(*, path: str) -> CustodyFileMetadata` — opens JSON custody file, computes shape metadata (utf-8 byte-length + sha256 hex of `str(value)`), returns.  Raw values held only in private local scope during computation; never assigned to any returned attribute.
- `NonCustodyPathRefused` — refuses paths outside `CUSTODY_PATH_PREFIXES`.
- `CustodyFileFormatUnsupportedError` — refuses non-JSON extensions (this CP scope; CSV / xlsx / raw-key follow-on).

**Refusals (2 new):** `NonCustodyPathRefused` · `CustodyFileFormatUnsupportedError`.

## §B · Wave-honest limits (owner constraint: "small")

1. **JSON custody only.**  CSV / xlsx / raw-key custody files refuse with `CustodyFileFormatUnsupportedError`.  Extension is a follow-on CP when a specific schema is standardised.  The current JUMP custody (CSV) is NOT supported through the helper today; probe tool has an opt-in CSV env-injection fallback.
2. **Top-level scalars only.**  The helper does not recurse into nested JSON.  Fields deeper than one level are stringified as `str(value)` and sha256'd; this is honest metadata but not structural traversal.
3. **No LLM / HTTP / filesystem-write.**  Read-only surface.
4. **Case-agnostic.**  No coupling to any specific custody schema.
5. **Structurally-safe surface** (Rec-2 restated): returned dataclasses have closed field sets; frozen-instance discipline enforced.  Attribute-name blacklist test verifies no `value`/`raw`/`secret`/`password`/`token`/`key`/`cred`/`auth` attribute can appear.
