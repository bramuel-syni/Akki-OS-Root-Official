- `assert_seam_has_ratified_backend(*, registry, seam_name) -> None` — load-bearing gate for future live-invocation paths; refuses `SeamHasNoRatifiedBackendError` when no ratified backend for the given seam_name.

## §B · Wave-honest limits (§E.5 grounding brief)

1. **METADATA-ONLY.** Registry does not call backends; it records their ratification state. Live-invocation paths remain untouched — each seam already refuses on invocation of an unratified backend per D10 discipline. The registry adds a QUERY surface, not an enforcement path.
2. **Case-agnostic.** No coupling to any specific pluggable seam class. Any Python string is a valid `seam_name` (semantic validation belongs to callers).
3. **Immutable surface.** `register_backend` returns a new `BackendRegistrySurface` (no in-place mutation); frozen-dataclass discipline enforced by `@dataclass(frozen=True)`.
4. **Deterministic output.** Insertion order preserved on read (Rec-3-M6SW6 verbatim "deterministic output").
5. **§3.1 P038 tokens-not-waveforms discipline preserved.**  No audio bytes / waveform / raw samples cross this surface; `seam_name` and `backend_name` are opaque tokens.
